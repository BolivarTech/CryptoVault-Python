# CryptoVault-Python

**A Python implementation of the [`cryptovault`](https://github.com/BolivarTech/cryptovault)
blob format, byte-compatible with the Rust crate.** This first stage covers the AEAD-only
`NoFec` mode: AES-256-GCM-SIV under an HKDF-SHA256 key, with no forward-error-correction layer.

> **Status: in development.** The format below is fixed and has been checked in both
> directions against `cryptovault` 0.3.0. The Python API is still being specified, so there
> is no release yet and no usage example to show. Both will arrive with the first tagged
> version.

---

## What it does

Two services that share one 32-byte key can encrypt and authenticate messages for each
other, and a blob produced on either side opens on the other: Rust → Python and
Python → Rust. The package opens no connections and knows nothing about transports. It
turns text into a blob and back, and the caller moves the blob.

The Rust crate stacks two independent layers: an AEAD that provides all of the security,
then an optional FEC that adds channel resilience and no security. This package implements
only the first layer, which is the wire format the Rust crate produces when built with its
`NoFec` strategy.

### Blob layout

```text
blob   = base64( header ‖ nonce(12 B) ‖ ciphertext ‖ tag(16 B) )      standard alphabet, padded
header = version (0x01) ‖ plaintext_len (u32, little-endian)
key    = HKDF-SHA256( salt = none, ikm = 32-byte master key, info = "cryptovault:v1:aead", L = 32 )
AAD    = 0x01 (data purpose) ‖ header
cipher = AES-256-GCM-SIV, fresh random 12-byte nonce per message
```

The header travels in the clear and is bound as associated data, so changing any bit of it
fails authentication. The version byte leaves room to evolve the format without breaking
existing blobs; today only `0x01` is accepted.

## Security model

| Property | Mechanism | Level |
|---|---|---|
| Confidentiality | AES-256-GCM-SIV (RFC 8452) | 256-bit key |
| Integrity / authenticity | 128-bit GCM-SIV tag, header bound as AAD | forgery ≤ 2⁻¹²⁸ per message |
| Nonce-misuse resistance | SIV construction | a nonce collision reveals only plaintext equality |
| Key separation | HKDF-SHA256 with a fixed `info` label | the AEAD key is never the raw master key |
| Opaque failures | one domain error for every decryption failure | no oracle on *which* check failed |
| Secret hygiene | no key, secret, blob or plaintext in errors, logs or `repr` | — |

All cryptographic primitives come from the
[`cryptography`](https://cryptography.io/) package. Nothing here is home-rolled crypto.

### Out of scope (what it does NOT defend against)

- **Weak keys.** This stage has no Argon2id and no passphrases: the master key must be 32
  uniformly random bytes. Anything else is rejected before any encryption or decryption.
- **Replay.** A valid blob stays valid. Detecting repeats is the caller's protocol concern.
- **Traffic analysis.** The header carries the plaintext length in the clear, and the blob
  size follows from it.
- **Channel errors.** Without FEC, a single flipped bit makes the blob fail authentication.
  That is the intended behavior: it fails closed and never decrypts to something wrong.
- **Host compromise.** A key in process memory is as safe as the process.

### Operational contracts (the caller must honor)

- **Use exactly 32 bytes of key.** A shorter or longer key is an error, not something the
  package pads or truncates.
- **Rekey before ~2⁴⁸ messages per key.** That is the birthday bound for random 96-bit
  nonces.
- **Decode with the same mode you encoded with.** A default `cryptovault::CryptoVault` in Rust
  wraps the blob in FEC, which this package cannot read. Interoperate with a Rust vault built
  with `NoFec`.
- **One blob, one message.** Framing and delivery belong to the caller.

## Requirements

- **Python 3.11** or newer.
- **`cryptography` 42 or newer**, linked against **OpenSSL 3.2 or newer** (AES-GCM-SIV needs it).
  The official wheels qualify, and this has been checked with `cryptography` 50.0.2 on
  OpenSSL 4.0.3.

## Roadmap

1. **`NoFec` blob format.** Encrypt and decrypt, cross-checked against blobs generated by the
   Rust crate in both directions. *In progress.*
2. **The rest of the crate.** The FEC layers and Argon2id key derivation, so any `cryptovault`
   blob can be read from Python.
